# notes

Follows [`protocols/notes.md`](../protocols/notes.md), with one structural
difference worth stating before anything else.

## Module notes are `doc.ts`, beside the code

The protocol's default is `notes/modules/`, ephemeral, roughly one per file, and
most of the corpus. **This repository puts that kind in a `doc.ts` in the
package it describes** — `lib/kernel/doc.ts`, `components/forms/button/doc.ts` —
and keeps `notes/` for the transferable kinds only.

Two reasons, and the second is the load-bearing one:

- A module note goes stale when its file changes, so it should be in the diff
  that changes it. A note in a parallel tree is a note nobody opens on the day
  it stops being true.
- `doc.ts` is also the **oracle** for a package's spec tests. Splitting it into
  a contract half and a mechanics half is what makes sanitising a section cut —
  see [`techniques/contract-and-mechanics-halves`](techniques/contract-and-mechanics-halves.md).
  A module note that lived in `notes/` could not do that job.

So the lopsided ratio the protocol describes still holds; the disposable half
just lives in the code tree. What is here is what survives this project.

```
  notes/
    substrate/   dependency-scoped, version-stamped — carries to any project using that thing
    patterns/    this architecture
    techniques/  broadly true, rarely stale
    language/    a language's own behaviour
```

`concepts/` has no entries: this is a template with no domain. When a product is
built from it, that is where its vocabulary goes.
